# Фильтры реального времени для интерактивного кино

Всё, что касается фильтров и искажений картинки из наших AR-игр (папка `ar/` в test-repo), собрано в одном месте и переделано так, чтобы фильтры работали **поверх видеофайла**, а не только поверх камеры. Монстров, мух и игровую логику сюда не брали.

Резюме проекта кино с дополнением про фильтры лежит рядом: [REZYUME.md](REZYUME.md).

**Проба в браузере (только GitHub, не GitVerse):** https://glebbelov85-tech.github.io/test-repo/test/kino-filtry/
Там отрезок «кабина в движении» из ваших материалов, стрелки ◀ ▶ для смены фильтра (с плавным переходом), ползунок «Сила», кнопка «Своё видео» (выбрать любой ролик с телефона) и кнопка «Сюжет» (мир плавно становится неоновым).

## Как это работает

1. Видео играет в спрятанном `<video>`.
2. Каждый кадр копируется в текстуру видеокарты (`texImage2D` из `<video>`).
3. Каждый второй кадр уменьшенная копия (320 px) кладётся в «ленту прошлого» из 48 кадров (это 1.6 с). Из неё берут кадры фильтры с ⏳.
4. Шейдер для каждого пикселя экрана вызывает `fx(номер фильтра, точка)`. Во время перехода он считает два фильтра и смешивает их, поэтому смена фильтра идёт плавным перетеканием, а не резким скачком (позиция может быть дробной: `f.setPos(1.5)`).
5. В конце результат смешивается с чистым видео по «силе» (`amount`).

## Как применить к видео в кино

```html
<canvas id="ekran" style="width:100vw;height:100vh"></canvas>
<video id="otrezok" playsinline muted hidden></video>
<script src="shader.js"></script>
<script src="filtry.js"></script>
<script src="kamera.js"></script>
<script>
  const video = document.getElementById('otrezok');
  const f = new Filtry(document.getElementById('ekran'), { fit: 'contain' });
  playVideoUrl(video, 'otrezki/pryamo.mp4', { loop: false });
  f.setSource(video);
  f.setEffectId(0);                       // обычное видео
  requestAnimationFrame(function loop(ts) { f.render(ts); requestAnimationFrame(loop); });

  // игрок выбрал «налево» -> по сюжету мир становится неоновым за 2 секунды
  function stanovitsyaNeonovym() {
    const ot = f.pos, k = Filtry.EFFECTS.findIndex(e => e.id === 13), t0 = performance.now();
    (function step(now) { const x = Math.min(1, (now - t0) / 2000); f.setPos(ot + (k - ot) * x); if (x < 1) requestAnimationFrame(step); })(t0);
  }
</script>
```

Важное для склейки отрезков:
- Видеофайлы должны лежать **на том же сайте**, что и игра. Видео с чужого сайта WebGL читать не даст (ошибка CORS), картинка будет чёрной.
- На склейке двух отрезков вызывайте `f.resetHistory()`, иначе фильтры с ⏳ полсекунды будут смешивать старый и новый отрезок. Хотя иногда это и красиво, как переход.
- Для бесшовной склейки удобно держать **два** `<video>`: пока играет один, второй уже загружен и стоит на первом кадре. В момент склейки делаем `f.setSource(второе)`, без паузы.
- Звук мотора лучше пускать отдельно через Web Audio, а видео держать без звука (`muted`): тогда браузер не мешает автозапуску.
- iPhone: обязательно `playsinline`, иначе он откроет видео своим плеером на весь экран.

Камеру можно оставить как бонус-режим: `startCamera(video, 'environment')` вместо `playVideoUrl`, остальное то же самое.

## Скорость на телефоне

- Нужен **WebGL2**: есть в Chrome на Android и в Safari на iPhone с iOS 15+. Без него остаётся `css-filtry.js`: он почти ничего не стоит, но умеет только менять цвета.
- Самые тяжёлые фильтры: **Неон** и **Мультфильм**. Каждый пиксель читает картинку 9–18 раз. На экране 1080×2400 это десятки миллионов чтений за кадр. На среднем Android ожидаю 30–60 кадров/с, на слабом может проседать до 15–25. Это оценка, на настоящем телефоне я ещё не мерил.
- Во время перехода между двумя фильтрами нагрузка удваивается (считаются оба). Переход длится 1–2 секунды, обычно это незаметно.
- Что помогает:
  - кнопка качества в демо (100% → 70% → 50%) или `new Filtry(canvas, { quality: 0.6 })`: картинка считается в меньшем разрешении и растягивается. Для видео 720p разница почти не видна, а скорость растёт примерно в 2–3 раза;
  - видео отрезков 720p, а не 4K: перекачка кадра в видеокарту тоже стоит времени;
  - лента прошлого: можно уменьшить `histN` (например, до 24) и `histW` (до 240), если нужна экономия памяти.
- Счётчик кадров «к/с» в правом верхнем углу демо показывает реальную скорость на конкретном телефоне. 30 и выше значит нормально.
- Мой счётчик в облаке показывал 3 к/с, но там нет видеокарты, всё считает процессор. Это не показатель для телефона.

## Ограничения

- Это стильный эффект поверх видео, а не настоящая перерисовка в мультфильм нейросетью. Мультфильм похож на рисованный, но мелкие детали и лица остаются как в видео.
- Фильтры «время» на паузе видео застывают (новые кадры в ленту не идут), это нормально.
- Запись (`zapis.js`) на iPhone работает не во всех версиях Safari. На Android в Chrome работает.
